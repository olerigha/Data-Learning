# Waterfall vs Agile
**In one line:** Waterfall finishes each phase before starting the next; Agile works in short, overlapping cycles with cross-functional teams and constant feedback.

**In plain words:** Waterfall runs requirements → design → build → test in strict order, so problems show up late and changes are costly. Agile delivers small working pieces every few weeks, shows them to users, and adjusts. That fits data science well, because you often don't know what will work until you try. Agile has mostly replaced waterfall for software.

**Terms**
| Term | Means |
|---|---|
| Waterfall | sequential phases: requirements → design → implementation → verification |
| Agile | iterative, overlapping work by cross-functional teams |
| SDLC | software development lifecycle |
| Fail fast | find what doesn't work early and cheaply |
| Agile methods | Scrum, Kanban, Extreme Programming (XP), Feature-Driven Development (FDD), Lean |

**Key points**
- **Agile benefits:** faster time to market, happier customers, values employees, less rework.
- **Agile traits:** transparent, constant communication, trust and teamwork, minimal documentation, pair programming, rough estimates, fail fast.
- Origin: Takeuchi and Nonaka, "The New New Product Development Game" (HBR, 1986).
