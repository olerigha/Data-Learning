# Managing Analytics Projects
**In one line:** Experienced analytics project managers expect the plan to change, keep stakeholders engaged, and treat the work as a series of experiments (Viaene & Van den Bunder, MIT Sloan Management Review, 2011).

**In plain words:** Analytics projects have fuzzy, shifting requirements and high risk of never being used. The managers who succeed still push hard to deliver, but they assume the first plan won't survive. They keep explaining and managing expectations, measure success by whether the results get *used* (and what everyone learned), and run good experiments: clear question, build, run, analyze, repeat.

**Terms**
| Term | Means |
|---|---|
| Delivery orientation | bias toward execution and on-time delivery |
| Value in use | value comes only when people actually use the output |
| Value of learning | what the organization learns has value even if a model fails |
| Intelligent experimentation | design → build → run → analyze cycle with clear goals |

**Key points** (the article's five practices)
1. Delivery orientation and a bias toward execution.
2. See value in use and value of learning.
3. Work to gain commitment from stakeholders.
4. Rely on intelligent experimentation (the scientific method).
5. Use information technology smartly.

**Memorize vs. look up:** Memorize the three headline findings (plans change, manage expectations, experiment).
