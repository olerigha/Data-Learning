# Gantt Charts and Critical Path
**In one line:** A Gantt chart shows tasks on a timeline; the critical path is the longest chain of dependent tasks, and it sets the earliest possible finish date.

**In plain words:** Some tasks must wait for others. Follow every chain of waiting tasks from start to finish: the longest one is the critical path. Any delay on it delays the whole project. Tasks off the critical path have "slack": they can slip a bit without hurting the end date. To finish sooner you either add resources (crashing) or overlap tasks (fast-tracking).

**Terms**
| Term | Means |
|---|---|
| Gantt chart | bar chart of tasks against time (e.g. MS Project) |
| Dependency | a task that must wait for another |
| Critical path | the zero-slack chain; sets minimum duration |
| Slack / float | how much a task can slip without delaying the project |
| Milestone | zero-duration checkpoint |
| Crashing | add resources to shorten tasks |
| Fast-tracking | overlap tasks that would normally run in sequence |

**Key points**
- Critical path matters because it answers "when will we finish?" and shows which tasks to watch.
- **Project arithmetic:** When will it end? When must I start to finish by a date? Where's the flex? Are we resource- or time-constrained? How can I make up time (shifts, overtime, more people)?

**Example:** A (3 days) → B (4 days) and A → C (2 days), with both B and C needed before D (1 day). The critical path is A → B → D = 8 days, and C has 2 days of slack.

**Memorize vs. look up:** Memorize critical path, slack, crashing vs fast-tracking.
