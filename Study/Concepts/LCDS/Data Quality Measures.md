# Data Quality Measures
**In one line:** Data quality has two sides: what IT can measure (objective) and whether the business trusts it (subjective). You need both.

**In plain words:** IT checks things like "are fields complete and consistent across systems?" Business users ask "do I believe this number and can I use it?" Neither alone is enough. Users' trust only rises after real, measurable fixes, and it rises slowly. So track the objective numbers, survey the perception, and keep improving in a loop.

**Terms**
| Term | Means |
|---|---|
| Objective (IT) measures | validity, completeness, integrity, consistency, uniqueness |
| Subjective (business) measures | clarity, believability, objectivity, relevancy, scarcity, timeliness, precision, accessibility |
| Data delivery | can users get it, find it, reach it, interpret it, and use it? |
| OODA loop | Observe → Orient → Decide → Act, repeated |
| Stage gate | a data-quality review required before release |
| Data steward | owner who acts on quality issues in their domain |

**Key points**
- Measure with surveys (perception), tool-based queries (objective), and third-party verification.
- Delivery questions: Can I get it? Find it? Get to it? Interpret it? Use it?
- 12-step program highlights: candidate KPIs/KRIs → profiling → dashboard → goals → standards → feed governance → delegate to stewards → enterprise DQ team → release stage gate → communicate benefits.

**Memorize vs. look up:** Memorize objective vs subjective and "perception lags real improvement".
